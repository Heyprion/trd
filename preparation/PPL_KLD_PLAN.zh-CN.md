原始40,315题经清洗得到33,236题，留出512题后训练池为32,724；首轮只使用其中9,984题。原始完整DeepScaleR版本继续保留作独立复现范围。模型正式训练过的数据不能事后划为独立留出集；这里的“未见”只指本次蒸馏，没有证据保证预训练未见。

## 3. 指标与口径

令 `S0` 为基线4B学生、`S1` 为正式蒸馏后4B学生、`T` 为固定8B教师。对于固定问题 `x_i` 和参考解答 `y_i`，让三个模型在相同题目提示和相同解答前缀下前向计算，只统计 response token。

### 主表

| 指标 | 比较 | 含义 |
| --- | --- | --- |
| response NLL / PPL | S0、S1；T作参照 | 对同一份参考解答的预测能力 |
| 全词表 forward KL，nats/token | KL(T || S0)、KL(T || S1) | 在固定参考前缀上的教师分布匹配程度 |
| 全词表 reverse KL，可同时计算 | KL(S0 || T)、KL(S1 || T) | 补充检查另一方向的分布差异 |
| 按题目配对的变化及95%区间 | S1相对S0 | 检查总体变化及题目间波动 |

公式：

```text
NLL(M) = sum_{i,t}[-log p_M(y_i,t | x_i, y_i,<t)] / N_tokens
PPL(M) = exp(NLL(M))
FKL(T || S) = sum_{i,t,v}[p_T(v | x_i,y_i,<t)
                         * (log p_T(v | x_i,y_i,<t)
                            - log p_S(v | x_i,y_i,<t))] / N_tokens
```

这里 KLD 指 KL divergence；训练中的 KD loss 可能还含温度平方、裁剪、缩放或其他项，必须写清口径。主指标采用温度1、全词表、不裁剪、不截取top-k、自然对数。PPL不能从KL直接推得：PPL读取参考token的概率，KL比较整个词表的概率分布。

所有模型必须固定 tokenizer、提示模板、response token IDs、预测位置、EOS规则、长度策略及mask。采用 `eval()`、关闭梯度和随机训练行为；同一参考前缀一次前向即可得到全部预测位置，无需逐token生成，也无需pass@16。用FP32完成log-softmax及KL归约，BF16存储模型权重；正式聚合先汇总NLL/KL总和与有效token总数，再计算比值及PPL，不能平均batch PPL。按题目而非独立token做配对bootstrap，例如1,000次，对每次重采样重新计算上述比值。

不应让S0和S1各生成自己的文本，再把各自在自己文本上的PPL作为前后主对比；文本及前缀变化会混入指标。也不能只计算一个实际token上的 `log p_T - log p_S` 并宣称它是全词表KL。

### TRD训练目标的补充分析

在独立的64–128题上，用基线学生生成一次 `y_o`，固定教师修订一次得到 `y_r`，并保存。S0与S1都沿同一份 `y_r` 评分；教师始终使用同一个 `x + y_o + 修订指令`，学生始终只用题目。这样得到的跨条件KL衡量训练目标的迁移，单独命名和报告，不与主表相同输入KL混合。主表和这张表的前缀分布都固定，均不宣称是S1实时on-policy KL或完整序列分布KL。

这一补充需要生成长解答，按需执行；主表可以直接利用现有非空参考解答，无需为512题新生成解答。原始参考解答和教师修订解答的PPL也不能混为一个指标。

## 4. 执行与资源

1. 冻结验证题目清单、参考文本、模板、mask规则与SHA256，记录抽样及去重规则。保留基线模型版本和正式训练产物版本。
2. 实现离线评分脚本：先做32题校准，检查response首token移位、词表映射、mask、计数、跨rank聚合和数值误差；记录端到端速度，更新排期。校准也上传SwanLab。
3. 正式训练前评分S0/T；训练后用相同清单评分S1/T。基线可以在训练后重新加载原始4B模型补测，只要保留了真正未参与蒸馏的验证集。
4. 主要产物为逐题NLL/KL总和、token数、截断标记，以及整体/长度分桶/训练对照结果、配对差值区间。所有模型实验上传SwanLab `trd-math-opd`，在HISTORY记录运行链接。

硬件沿用2×RTX PRO 6000 96GB和BF16/FlashAttention；评分不需要优化器、反向传播和梯度检查点。实际脚本使用每卡完整师生副本、互不重复的数据batch，默认batch最多8条、padded token预算8,192，不直接沿用训练batch。取隐藏状态后仅对response位置分块调用LM head和全词表KL，避免生成/保存完整教师logits：当前234,375个参考token的BF16全词表教师分布，按151,936词表估计就约71.2GB（66.3GiB）。保存逐题统计足够支持汇总与bootstrap；要重算分布指标时重新前向。

## 5. 耗时预估

以下均不包含正式蒸馏训练，不包含最终benchmark生成。当前没有运行专门的PPL/KLD性能测试；区间为排期估计，不是实测承诺。

既有balanced训练吞吐约7.1K response tokens/s，包括一对师生的前向与训练更新，且主要测的是构造长序列。它不能直接当作三模型评分速度。对“教师 + S0 + S1、两个全词表KL”的合计处理，暂按 **1–4K固定参考位置/秒** 做保守预算，实际由32题校准替换；提示长度、batch、加载路径会改变结果。

```text
总时长 ≈ 启动/模型加载 + 固定参考token总数 / 三模型合计评分吞吐
         + 数据读取/汇总/上传 + 必要的重载开销
```

| 范围 | 两个学生版本和固定教师的评分总预算 |
| --- | --- |
| 32题校准 | 2–10分钟，可能由启动占主导 |
| 当前512题非空参考解答主表，约23.4万response tokens | 10–30分钟 |
| 主表再加128题训练对照、统计汇总 | 15–40分钟 |
| 1,024题类似长度的参考解答 | 15–45分钟 |
| 清洗后全部6,305条非空参考解答，仅作规模估算 | 0.5–2小时；只有真正留出的题目可称验证结果 |
| 可选64–128题TRD长轨迹补充，包含一次学生生成与教师修订 | 0.5–2小时；大量触及16K输出上限可能更久 |

当前512题约23.4万token的纯评分计算按上述吞吐约1–4分钟；表内预留了冷启动、基线/终点分开运行、跨卡统计及上传开销。只做S1补测时也不应简单按总预算除以二，仍可能要重新加载教师和进程。长轨迹生成的预测置信度更低，参考已有8题/1K上限真实rollout记录，而非拿包含冷启动的296.9秒按题目数放大。

脚本开发、校验、SwanLab接入及首份报告另预留 **2–4小时人工/工程时间**。推荐本轮投入为：一次开发约半天以内，主指标GPU运行预留约半小时；后续复用相同脚本与数据。TRD长轨迹分析作为单独预算。

## 6. 如何解释结果

- 留出集PPL下降：对该参考解答分布的预测改善；并不直接等于数学正确率提高。
- 留出集KL下降：在所测固定前缀分布上更接近教师；不保证完整生成过程更接近，也不保证教师一定正确。
- 训练对照改善、验证集不改善或变差：提示拟合局限或过拟合，应结合样本长度、参考风格与误差分析判断。
- PPL与KL可以走向不同；两者不要求同步下降。TRD论文也展示了某些失败轨迹上的KL接近零，不能把“KL越小”无条件等价为推理越好。
- 后续用保持独立的数学benchmark准确率补齐能力证据。本轮先建立固定口径，不预设或编造指标降幅。
