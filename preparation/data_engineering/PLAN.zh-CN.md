# 数学数据工程：一小时自动清洗与三档分层

更新：2026-11-15。用户本轮要求优先于上一版方案；上一版三类清单、四档标签、人工复核和额外完整解题校准方案停止采用。

## 1. 交付约束

- 清洗只有两种结果：可用、排除。无需用户人工参与；规则或模型不能自动闭环的样本直接排除，记录原因。
- 先清洗，只有通过清洗的题进入标签阶段。缺关键图片、缺条件、缺答案、题目中泄露目标答案等在清洗阶段排除。
- 每道最终可用题都有数学领域和易／中／难标签。来源标签冲突的题排除；无原始标签的题自动标注。
- 正式批处理以端到端运行不超过60分钟为目标，包含模型加载、测速、清洗、标签、导出与上传。脚本首次开发时间另计。本轮只修订方案，没有运行GPU实验。

## 2. 已有数据依据

DeepScaleR共40,315题；原文重复冗余928条，去空白后重复候选冗余1,282条，其中177个题组答案文本不同；空答案6条；Asymptote标记958条、外链图片标记19条。已确认训练行5696与BeyondAIME索引30为同一道染色题，测试仅追加答案mod1000。完整数值与数据哈希保留在`audit-summary.json`。

Omni-MATH来源记录匹配到本地3,528行，其中3,469行单一匹配，3,468行同时通过现有答案判等；59行存在多匹配，其中31行难度冲突。按本轮规则，冲突直接导致排除，不再追查或修复。

空参考解答solution有32,924条，这是上游允许的情况，当前OPD也不使用参考解答；只要题目完整、答案有效，保留。缺答案answer与缺参考解答solution分别处理。

## 3. 完整执行流程

### A. CPU规则清洗、精确去重和来源匹配

用分块多进程处理，worker初始16，处理较重且确有吞吐收益时增至32；轻量扫描直接单进程或向量化。数据留在内存中复用，避免每个worker重复读取或复制完整数据。

| 条件 | 自动决策 |
| --- | --- |
| 空题干、空答案、严重乱码或明显残缺 | 排除 |
| 参考解答为空，但题目和答案正常 | 可继续清洗 |
| 同题、答案经安全格式规范化后相同 | 留一条，固定排序选择代表；其余排除 |
| 同题答案不能自动证明等价 | 整个题组排除；不花时间修复 |
| 原始来源的答案、领域或难度标签冲突 | 整个对应题组排除 |
| 与最终测试题相同或同题改写 | 训练侧整个题组排除 |
| 数学表达式、分数、完整选择题 | 保留继续处理；不要求答案必须是整数 |

保留原始文本；规范化只用于匹配和安全的外层格式处理，不删除数学运算符或改动数字。符号等价工具只走有严格超时的快路径，超时后按本表直接排除。同样题型但条件、数字不同的题不自动合并。

### B. GPU辅助近重复判定

CPU以n-gram及MinHash/LSH召回近重复候选，覆盖训练内部和训练—测试比较；不做40,315题全量两两大模型判断。GPU批量比较候选的条件、数字、问法和答案变换，输出短决策码。同题且标准答案相容则合并；训练—测试同题则排除训练组；不能明确区分的高相似候选组按保守规则排除。

已确认的二十面体染色题直接加入排除规则。对正常换数字题，GPU明确判为不同实例则保留。候选阈值、判定码和组成员保存，后续可以重建排除过程，不增加人工环节。此策略是有成本上限的近重复筛选，不宣称完整语义等价证明。

### C. GPU内容清洗：只判断是否可用

两卡各运行一个Qwen3-8B BF16副本，TP=1。对通过A/B的题执行短输出内容筛查，检查：

- 是否具备完整条件和明确求解目标；是否只有解答片段。
- 是否依赖缺失的关键图片、图示定义或外部上下文。
- 是否在题干直接泄露所求答案。
- 标准答案是否明显残缺或与问题要求矛盾。

只返回`A`或`R+原因码`，输出上限8 tokens。原始answer可以作为独立字段供清洗判断；不能因为存在gold字段，就认为题干泄露答案。可用的参考解答仅在有明确矛盾证据时辅助判断，不按“最后boxed未判等”批量排除。

有Asymptote或“figure”不自动排除：文字或代码中信息完整可保留，缺关键图形信息则排除。模型无法明确认定可用时直接排除。此阶段只负责清洗，不输出难度或领域标签。

### D. 只对清洗通过的题打标签

可靠原始标签优先使用：来源匹配唯一或多匹配标签完全一致、答案兼容、字段有效。映射到固定领域表；原Omni难度先按≤3为易、>3且≤5为中、>5为难作工程三档映射，保存原分数及映射版本。这是固定的粗分层口径，不宣称是4B实测成功率。

没有原始标签的可用题，沿用已加载的两个8B副本自动标注。输入只有题目及简短固定示例，不输入gold答案，不生成完整解答。输出领域码和难度码，例如`2,3`，上限8 tokens：

| 字段 | 允许值 |
| --- | --- |
| 主领域 | 代数、几何、数论、组合与概率、微积分、其他 |
| 难度 | 易、中、难 |

易：基础概念、常规计算或直接套用常用方法；中：多步推导、常见竞赛技巧；难：奥赛级构造、较强综合推理或非常规方法。提供与原始量表一致的锚点示例，保持提示版本固定。

模型格式非法、超时或无法产生合法标签，最多自动短重试一次，仍失败则排除该题。最终可用表的领域和难度必须合法且非空。清洗风险不进入标签选项。

## 4. 并行与GPU安排

当前进程可见208逻辑CPU、约1TiB系统内存；可见资源不代表需要把worker全开。CPU多进程的序列化、内存带宽及符号工具开销同样需要控制。

| 工作 | 资源安排 |
| --- | --- |
| 文本规范化、哈希、来源join、近重复候选 | CPU16–32个worker，按批处理 |
| 候选同题判断、内容筛查、自动标签 | 双卡两个8B副本，各自处理独立数据 |
| GPU并发 | 每卡max_num_seqs先64，256题短测速后尝试128，选择实测吞吐较高且稳定的配置 |
| GPU token批预算 | 32,768起步，若prefill受限且显存有余量，测速65,536 |
| 其他 | BF16、TP1、显存份额0.85、enable_thinking=False、复用公共前缀缓存，模型全程常驻 |
| 短请求预算 | max_model_len=4096；清洗和标签各max_tokens=8；超长输入直接排除并记原因，不截断题目后假称完整 |

增加客户端worker主要负责持续供给请求，实际GPU并行由vLLM批调度决定；并发增加只保留有实测收益的配置。两卡副本和批调度选项参照本机vLLM0.11.0文档：[数据并行](https://docs.vllm.ai/en/v0.11.0/serving/data_parallel_deployment.html)、[吞吐调优](https://docs.vllm.ai/en/v0.11.0/configuration/optimization.html)。

精确哈希/字符串处理保留CPU：上轮包含token化、来源匹配及测试候选扫描的分析段已约19.4秒，尚无证据表明迁移GPU更快。GPU用于收益更明确的模型判断，去重候选也使用GPU判定；不为单次4万短题引入新embedding模型下载与额外部署。若后续实际测速证明某算子GPU更快，再替换执行后端。

## 5. 60分钟执行预算

CPU规则处理与两个GPU模型加载同时进行，模型不重复加载；同一批题依次通过清洗和标签门槛，失败即退出。

| 从启动起的目标时间 | 工作 |
| --- | --- |
| 0–5分钟 | CPU基础过滤/精确去重/来源匹配；同时加载两个8B，完成256题短测速 |
| 5–25分钟 | GPU近重复候选判定和内容清洗，CPU持续供给与聚合 |
| 25–45分钟 | 给可用题回填原标签或生成短标签；完成有限短重试 |
| 45–55分钟 | 排重闭环、标签合法性检查、导出和统计 |
| 55–60分钟 | 收尾与SwanLab上传缓冲 |

40,315题按清洗8 tokens、标签8 tokens的两轮输出上限，合计约64.5万tokens，加少量候选判断和重试。假设两卡合计decode500–2,000 tokens/s，主体纯decode约5.4–21.5分钟；模型加载、prefill和排队另计。相比上一版32–64 tokens长标签，本版用编码输出大幅压缩生成量。

这些是运行预算，尚未经本机GPU实测；首次256题必须同时测清洗、标签及候选判断并据此估计全量。到45分钟停止追加复杂判断和新重试；到55分钟仍未成功完成处理的记录按技术超时排除，单独统计，不能记成内容坏题或隐瞒覆盖损失。任务顺序固定种子打散，减少截止时的来源顺序偏差。全部最终记录只有可用或排除，不保留人工任务。

首版不做学生多次解题、教师长解答、全量逐步推理验证、题目修复、课程学习或额外模型训练。以自动质量筛选和粗分层控制成本，后续训练自然生成的表现可以作为单独统计更新，不阻塞本次交付。

## 6. 最终交付与验收

- `usable`：题目、答案、原参考解答、领域、易中难、标签来源、原始ID、数据版本。
- `excluded`：原始ID、原因码、关联重复组；没有人工任务列表。
- 汇总：可用/排除数量，各原因计数，易中难及领域分布，标签来源比例，技术失败数量，墙钟耗时与双卡吞吐。原数据和原始日志只保留本地。
- 自动检查：最终标签只含合法领域与三档难度；可用表必填字段非空；确认的测试同题全部移出训练侧；重复组无冲突代表；每条输入有唯一最终去向；清洗原因不混入分层字段。
- 训练数据目录及生成缓存按data_version隔离，保留原始版本；本轮不额外划分512题验证集，不改变正式评测口径。若后续启用验证集，再按题组划分。
- 所有实际批处理实验上传SwanLab并写HISTORY。此前CPU审计：[v2记录](https://swanlab.cn/@WangZIyu/trd-math-opd/runs/ksp7x0ba)；审计代码和小型摘要继续保留。

方法依据仍为DeepScaleR原数据约定、Big-Math的去重及测试排重、Omni-MATH的领域/难度标签；按本轮时间和自动化约束简化执行，不再保留上一版的人工闭环。
