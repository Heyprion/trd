# 数学 OPD/TRD 数据清洗与难度分层方案

日期：2026-11-15。范围：本机 DeepScaleR，Qwen3-4B-Instruct-2507 学生 / Qwen3-8B 教师，2×RTX PRO 6000 96GB。本次完成只读数据审计和方案，没有清洗覆盖训练文件，没有启动 GPU 标注、生成或训练。

建议先做可追溯的规则清洗、去重和测试集排重，回填能找回的原始标签，再以 8B 非思考模式短输出补齐粗粒度先验标签。与学生能力相关的难度主要复用后续必需的 y_o/y_r，必要时才做少量多次采样校准。首版目标是以小时级 GPU 成本得到可用的数据版本，不能宣称得到每题精确解题概率。

## 1. 出发点与实查结果

数据工程要解决三个实际问题：坏题和错标污染判分；重复题及测试题重合影响有效样本量与评测；缺乏可追溯的难度标签使后续采样无法解释。数据质量、题目难度、模型解题成本分别记录，不能把任一项当作另一项的替代。

审计读取本地完整原始 JSON、训练 parquet、五套实际使用的测试 parquet 和本地学生 tokenizer；核对训练 parquet 逐行等于原始 JSON。固定随机种子 20261115 抽取 64 题浏览，并查看重复冲突、图形、空答案和测试重合候选。原始数据和逐题结果保留本地，Git 只保存脚本、小型摘要和文档。

| 实查项目 | 结果 | 对方案的影响 |
| --- | --- | --- |
| 规模和字段 | 40,315 条；只有 problem / answer / solution | 没有可直接使用的逐题来源、领域和难度列 |
| 缺失 | problem 无空值；answer 空 6 条；solution 空 32,924 条，81.7% | 空 solution 符合上游约定，保留；空 answer 进入待修复池 |
| 参考解答 | 非空 7,391 条 | 可构建固定参考评估集，但不能代表全体题型分布 |
| 重复 | 原文完全相同的冗余 928 条；NFC 加去空白后 950 组、冗余 1,282 条 | 先处理低成本、可解释的重复；1,282 是候选冗余量，不是本次已删除量 |
| 同题答案不同 | 177 组，按答案文本区分 | 同时包括等价格式和实质矛盾，必须先核实再选保留版本 |
| 答案格式粗分类 | 整数 23,205；小数 1,504；字母候选 48；表达式及其他 15,558 | 不能按“非数字”删题；判分要覆盖符号、分数、集合和选项 |

| 训练—测试重合 | 规范化文本全等 0 对；trigram Jaccard≥0.5 候选 1 对 | 已人工阅读核实为同一题追加模 1000；仅查全等不足够 |

三个具体证据：

- 原始行 786 / 1401 是同一道合作做纸杯蛋糕的题，两人分别每 20 / 30 秒完成一个，5 分钟共 25 个，却分别标为 25 和 20；两条参考解答都算到 25。说明既不能任取首条，也不能只看是否有解答。
- 行 5696 的二十面体染色题与 BeyondAIME 本地索引 30 是相同核心题，测试版本额外要求答案模 1000；训练答案 61917364224 对应测试答案 224。清洗版本应移出训练侧整个题组。
- 随机样本行 65 要求读取图中 x/y，却没有图或可替代定义；行 9833 的 problem 是包含计算和结论的家庭购车解答片段。另有正常几何题带完整 Asymptote、完整条件，不能全部删掉。

参考解答的快速检查也显示现有 grader 的局限：7,391 条非空解答中，2,084 条最后 boxed 与 answer 被现有规则判等，2,376 条未能判等，2,930 条没有可抽取的最后 boxed，1 条 boxed 提取异常。**这些数不能解释为错误率**，因为选项字母和数值混排、单位、符号等价、非 boxed 结论均可能导致未判等。

## 2. 清洗与筛选：规则先行，疑难样本分流

所有输入保持只读。每题使用原始 revision + 原始行号构成 raw_id，另保存题干内容哈希和 duplicate_group_id；修复、合并、排重原因写入 manifest，保留旧值及证据，能够重建每个版本。

### 2.1 基础规范化和硬问题

- 检查字段类型、空题干、空答案、编码损坏和明显残缺片段。原题原答案保留；统一换行、首尾空白、Unicode NFC；保留数值、大小写、负号、不等号和 LaTeX 语义。
- 空答案 6 条先隔离并尝试依据可信原始来源恢复；不能恢复的暂不纳入“答案可验证”主池。当前 OPD 的 KL 计算本身未必需要 gold answer，但工程主池需要可靠判分和分层依据。
- 空 solution 不删除、不补写 32,924 条参考解答。当前 OPD 教师条件为题目 + 初始解答，源码没有使用专家解答；后续若做 OPSD 或参考 PPL，单独选择经过核验的非空解答子集。
- 缺失图片且缺少关键条件、只有解答片段而无完整任务、无法修复的歧义题进入 quarantine。轻量模型只负责标记风险，不能独自决定把所有可疑题删掉。

### 2.2 去重与测试排重

1. 对原文、保守规范化文本建立哈希组；确认规范化没有合并不同含义的短题。答案等价且题干相同的组只保留一条，优先可靠来源、已核验且更完整的版本。
2. 同题不同答案：先去除答案外层格式，再用数值和数学等价规则核实；像 16 与 16:1 需要结合题意。实质矛盾不能按多数投票或首条直接覆盖，不能解决则隔离整个组。
3. 近重复用 CPU token/字符 n-gram + MinHash/LSH 召回候选，避免全量两两比较；检查数值、条件和问法后决定是否合并。“同题型换数字”先作为题族保留，不自动视为重复。
4. 所有 229 道最终测试题与训练做全等及宽松近似召回；额外识别模数变换、改写和新增回答指令。确认同一题时从训练侧移除整个组，测试集不改。
5. 零全等匹配不能证明完全无污染。本次只完成文本全等及一种 lexical 候选扫描；完整近似排重尚待实现。

### 2.3 数学格式与可验证性

- 主池保留整数、分数、根式、表达式、集合、区间及题意明确的多问答案；不对数学内容做任意简化或把分数统一改成浮点。
- 选择题保留完整选项；能够明确解析时保存“字母—选项内容—标准答案”的映射。首版不批量删选项或改写为开放题，避免改变任务及误伤答案映射。
- Asymptote 代码保留。区分文字条件充分、代码提供必要图形信息、关键图形彻底缺失三种状态。`figure`、`prove` 等关键词仅为线索。
- 判分输出至少有 correct / incorrect / unverifiable / error，另外记录 truncated。解析失败和超时不自动等于答错；为符号工具设置每题超时、缓存和独立进程边界。
- 保留现有复现 grader；新增规范化与 Math-Verify 作为数据审计工具，报告两者差异，暂不静默改变正式 benchmark 分数定义。只对少量未解决候选追加 8B 复核或查原来源。

建议形成 accepted / quarantine / excluded 三类清单，分别表示可用、需核查、确认排除；重复冗余的原始行也仍可追踪。首版允许存在 unknown，避免为了标签覆盖率强行判断。

## 3. 难度分层：原始标签、先验难度和学生表现分别保存

难度既与题本身有关，也取决于学生模型、提示和生成预算。题干长度、解答长度、某次 KL/PPL、一次答错均不能直接作为难度真值。

### 3.1 先回填原始标签

从官方 KbsdJames/Omni-MATH 下载并固定 revision `40ba231d8f16e29ecd40e6407e2c8640145a8f62`，对同一原题做保守匹配，不改变训练题内容。实查 4,428 条原始记录可以匹配到本地 3,528 条训练行；其中 3,469 条为单一来源记录匹配，3,468 条同时通过现有答案判等。另有 59 条训练行匹配多个来源记录，其中 31 条的原难度值冲突，必须保留冲突信息。不能任选一个标签，也不能把 3,587 个匹配对误报为独立题目数。

回填 native_difficulty / native_domain / native_source / matched_source_id / revision / match_status。原始 Omni 难度来自 AoPS 评级及模型辅助评分，并非所有分值都是逐题人工测量的能力真值。原始量表保持原样，不与新模型评分直接平均；其他来源暂不可靠匹配时标 unknown，不从数据行号推断来源。

### 3.2 用 8B 短输出补先验标签

对缺少标签的可用题，使用本地 Qwen3-8B，一次返回结构化短结果，同时标领域、先验难度和题干风险；不要求完整解题。

| 字段 | 首版建议 |
| --- | --- |
| prior_level | easy / medium / hard / unknown；按固定示例和所需数学工具粗分 |
| domain | 代数、几何、数论、组合/概率、其他，可多选 |
| quality_flags | missing_context、diagram_dependency、answer_in_problem、ambiguous 等 |
| label_source | native / teacher_rubric / unresolved |
| label_evidence | 原来源或简短理由码；保存模型与模板版本 |

统一基准示例覆盖基础运算、一般竞赛和奥赛题；使用原始标签且无冲突的样本作为部分锚点。先验 easy 不是“4B 必然答对”，先验 hard 也不是“教师不能教”。模型自报 confidence 只用于复核排序，必须经抽查才能解释为可靠性。

标注采用教师非思考模式 `enable_thinking=False`，目标平均 32–64 个输出 token，上限先设 96，结构解析失败最多一次短重试；记录重试和截断，不让异常题无限生成。只输入题目及固定 rubric，原则上不输入 gold answer，减少答案泄露和不对称参考信息对难度评分的影响。缺少原标签或风险不确定的题优先处理，不必为了全覆盖立即重标已可靠回填的题。

抽查约 100–200 条，覆盖三档、unknown、各领域和风险标记，并对少量题重复标注检查一致性。若三档与后续学生表现没有区分度，就降低对标签的信任、修改 rubric，而不是靠模型主观标签直接做强筛选。

### 3.3 复用 y_o/y_r 建立与本机师生相关的观测

目前生成入口保存 responses，没有主动计算逐条数学 reward，y_r_prepare 中缺省 reward=0 也不是实际判分。需要在生成后显式加入评分，不能把旧 metadata 的 reward 当正确率。保存 finish_reason、token 数及实际采样配置；当前生成脚本还未保留完整这些元信息，应在实施阶段补齐。

已有 OPD/TRD 必需的学生 y_o、教师修订 y_r 可以产生以下行为分组，额外成本主要是 CPU 判分：

| 本次观测 | 含义与用途 |
| --- | --- |
| 学生答对、教师修订也答对 | 已掌握候选，保留一定覆盖 |
| 学生答错、教师修订答对 | 可迁移候选，后续重点分析是否更有蒸馏收益 |
| 学生答对、教师修订答错 | 修订退化风险，检查 gold 和生成轨迹 |
| 两者均未答对 | 较难或标注/判分有问题，需区分后处理 |
| 无法判定或触及预算 | 独立状态，不能当成最难或坏题 |

这些是单次行为观测，不等同于题目固有等级。教师修订使用学生初始解答，不是教师独立解题成功率；若需要独立师生能力差异，另抽少量题用相同 problem-only 提示评估。

首版可选从训练侧、按领域×先验难度抽 256 题，每题额外 2 次学生采样，输出 cap 4,096，用于检查各档平均成功率、截断率及判分覆盖；若连粗粒度区分都无法稳定建立，再对少数临界题扩到 4–8 次。n=2 只有很粗的观测，不生成“精确 p”；保留 k/n、预算、区间或低置信标记。短预算结果命名为 budgeted solve rate，不能代替正式 16,384 预算难度。自适应追加样本时也不能直接把停止时 k/n 当无偏估计。

如果暂时尚未运行全量 y_o/y_r，先交付先验分层版本；行为分组随正常生成补齐，无需为了数据工程提前花费整个训练数据生成时间。

## 4. 双卡执行与时间控制

CPU 完成字段检查、哈希去重、候选召回、元数据 join、token 长度和大部分判分。审计 v2 的实际分析段约 19.4 秒，不含导入、SwanLab 连接和文件下载；完整近重复筛选、工具超时及样本复核另计。

8B 短标注采用每卡一个 BF16 vLLM 副本、TP=1，数据分成两个不重叠 shard；两卡共同完成同一批标注。沿用 balanced 的 rollout 显存份额 0.85、max_num_seqs=16 及 34,816 token 批预算为起点，不把 FSDP2 训练并行方式搬到离线标签生成。4B 校准也使用两卡独立副本，按阶段加载，避免频繁切模型。更高并发只有吞吐和显存实测后再调整，不在首版追加量化、embedding 模型训练或分类器训练。

先做 256 题短标注测速，观察输出解析率、平均长度、重复标签一致性与两卡合计实际吞吐，核对关闭思考确实生效；再决定全量。以下是排期假设，并非本次 GPU 实测：

| 阶段 | 资源与首轮预算 |
| --- | --- |
| 字段、精确去重、元数据回填 | CPU 秒级到数分钟；本次审计已完成 |
| 完整近重复候选与复核、清洗报告 | CPU 为主，约 15–60 分钟，人工判断/难例修复另计 |
| 256 题短标注校准 | 双卡约 5–15 分钟，含加载和检查 |
| 约 3.6–4 万题短标签 | 双卡预留约 0.5–2 小时；低吞吐、较长输入或重试多时可超过此范围 |
| 可选 256×2 次学生解题校准 | 双卡约 0.5–1.5 小时，触顶较多时上调 |
| 全量 y_o/y_r 的判分回填 | 复用正常生成产物；CPU 先快路径，少量符号难例单独排队 |

估算公式：输出 token 数 / 两卡合计 decode 吞吐，再加 prefill、冷启动、长尾和检查。以 4 万题×平均 64 输出 token 约 256 万 token、合计 500–2,000 token/s 假设，纯 decode 约 21–85 分钟；max_tokens=96 对应近 387 万的上界预算，不能把 64 平均当保证。可选校准 256×2×cap4096 的输出上界约 210 万 token，纯 decode 约 18–70 分钟。吞吐假设必须被本机首次短测试替换。

不建议给 40,315 题预先做 4–8 次长解题。即使 4 次、平均每次 2,000 token，也约 3.23 亿输出 token；同一吞吐假设下纯 decode 约 45–179 小时。GPU 大显存不消除逐 token 解码成本。Big-Math 的每题 64 次采样可以作为方法参考，不能原样搬到当前时间预算。

首版按 **CPU/复核约 1 小时量级，GPU 预留 1–3 小时；可选能力校准另加 0.5–1.5 小时** 安排。端到端脚本、标注模板、断点续跑与评分联调开发另计半天到一天；这是工程估计，不含正式训练及其完整 y_o/y_r 生成。

## 5. 数据版本、划分与训练使用

建议产物为 raw manifest、clean pool、quarantine/rejected 清单、metadata/difficulty 表、训练/验证 ID 清单、分布与规则报告。数据保存在 `data/processed/math-v1/` 等被 Git 忽略的目录，日志在 `preparation/logs/data-engineering/`；代码、规则配置、SHA256 和小型统计表入 Git。筛选规则、数据版本、模型版本、随机种子、逐类保留/排除数量、难度覆盖、长度与判分覆盖上传 SwanLab，链接写入 HISTORY。

实施入口以独立数据构建脚本和规则配置为主，导出与当前 Hugging Face Dataset 三字段兼容的训练目录；额外 metadata 通过稳定 ID 关联。需要调整 `y_o_prepare.py` 把 raw_id / duplicate_group_id / data_version 等带入 extra_info，避免筛选后只剩重新编号的行号；`y_r_prepare.py` 已复制 extra_info，可继续传递。生成后评分独立实现，暂不改 KL loss。每个数据版本使用独立 GEN_RESULTS_ROOT，并在复用 parquet 前核验输入 ID 清单、数据哈希和生成配置；当前 prepare_training_data.py 仅检查文件存在且非空，相同 RUN_DATE 或显式 DATA_PATH 下可能复用旧版本数据。

先按题目及近重复组完成排重，再分组划分 train / validation，确保一个题组不跨两侧；最终五套 benchmark 始终独立。可与已有 PPL/KLD 方案对齐，留出 512 条经核验、非空参考解答的独立题组，并排除已知 pilot 来源。它是有参考解答子分布的验证集；另抽覆盖无解答题的训练侧开发样本核查分层，不能假称 512 题代表全量。当前验证集仍未落地，512 是建议规模。

严格全量复现保留原始 40,315 条入口和独立版本；clean-v1 是数据工程改动后的探索版本，两者在报告中区分。用于比较“清洗/分层是否有效”的实验应共享冻结测试与验证集，并报告剔除重合和留出样本后的实际训练范围；不把原始全集训练和留出后模型的差异全部归因于某个清洗规则。

首轮只完成 clean-v1 + 标签与统计，训练先保留清洗后自然分布。不预设 easy/medium/hard=某个比例，不立即叠加 curriculum。要测试难度采样时，再与同一 clean-v1 的自然分布对照，固定种子、优化器设置及训练 token/生成预算，并报告领域与长度分布变化。

对生成轨迹的 verified-target 筛选另建版本：确认教师目标答错或损坏可以隔离该轨迹，学生 y_o 答错本身不删除题目，因为它可能正是教师修订的有用场景。只保留“两者都答对”会改变训练分布，也偏离 TRD 的纠错出发点。

首版验收关注：规则和删改原因是否可重建；确认测试重合是否从训练侧全部移除；同题跨 split 数是否为 0；高风险排除样本及 accepted 样本的分层抽查；标签覆盖/冲突/unknown 比例；各领域、长度及非空解答比例的清洗前后变化；短标注解析率与真实资源成本。数据覆盖不足时保留 unknown，不用更多 GPU 强行制造高置信标签。

## 6. 论文与工程借鉴的边界

- [DeepScaleR 原数据卡](https://huggingface.co/datasets/agentica-org/DeepScaleR-Preview-Dataset/blob/b6ae8c60f5c1f2b594e2140b91c49c9ad0949e29/README.md)：明确 solution 可以为空，来源包括 AIME、AMC、Omni-MATH 和 Still。这直接决定空参考解答的处理。
- [Big-Math](https://arxiv.org/html/2502.17387v1)：借鉴可验证性、去重、测试排重及逐步抽查；其 aggressive 语义相似阈值、选择题删除和 64 rollout 难度估计不直接沿用到本项目。
- [Omni-MATH 论文](https://arxiv.org/html/2410.07985v1)与[官方数据](https://huggingface.co/datasets/KbsdJames/Omni-MATH/tree/40ba231d8f16e29ecd40e6407e2c8640145a8f62)：借鉴领域/难度分开保存；本地已验证可以恢复一部分真实来源标签。
- [Open R1 Update #3](https://huggingface.co/blog/open-r1/update-3)：借鉴对原答案、重解析答案及多种验证结果分别存储；其过滤分析提示只用规则验证会改变题型覆盖。当前只为不确定子集增加复核，不引入 70B 全量 judge。
- [DAPO](https://arxiv.org/html/2503.14476v1)：理解中间成功率样本的价值；其删除全对/全错 group 是 GRPO advantage 相关设计，当前 forward KL 蒸馏在这些题上仍可能有非零梯度，不能照搬成硬过滤条件。
- [Qwen3-8B 官方模型卡](https://huggingface.co/Qwen/Qwen3-8B)：非思考模式用于短标签；本地 tokenizer 模板已核对支持 enable_thinking。关闭思考只用于工程标注，不改变正式教师修订配置。

上述首版流程与时间预算是结合本机数据做出的工程选择，不是这些论文证明本项目一定有质量提升。效果需要后续固定预算的训练对照确认。
