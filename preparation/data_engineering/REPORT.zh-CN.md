更新日期：2026-11-15。本文是当前数学数据工程和数据使用范围的依据；早期`PLAN.zh-CN.md`保留方案演变，执行入口与参数见`README.zh-CN.md`。当前工作模型为Qwen3-4B-Instruct-2507学生、Qwen3-8B教师，硬件为2×RTX PRO 6000 Blackwell 96GB。

当前已完成原始数据审计、全量自动清洗、领域/难度分层和实际数据划分。验证集512题已冻结；其余32,724题构成暂定训练池，首轮只使用其中9,984题，剩余22,740题留作扩充。没有启动本次划分后的正式生成、训练或验证评分。

## 2. 原始数据观察

采用固定种子20261115浏览随机64题，并额外查看重复冲突、空答案、图形依赖和测试重合候选；全量字段、格式及token统计由`audit.py`完成。主要观察如下：

| 项目 | 原始观察 |
| --- | ---: |
| 总题数 | 40,315 |
| 空题干 | 0 |
| 空标准答案 | 6 |
| 空参考解答 | 32,924，约81.7% |
| 非空参考解答 | 7,391 |
| 原文完全相同的重复冗余 | 928条 |
| 早期NFC/去空白审计的重复候选 | 950组，冗余1,282条 |
| 上述重复组中答案文本不同 | 177组 |
| Asymptote标记 | 958题 |
| 外链图片标记 | 19题 |
| 常见图形词 | 782题 |
| 常见选择题标记 | 415题 |

这些启发式标记可交叉、也不穷尽，数量不等于实际坏题数。早期去空白统计与正式按词元边界匹配的实现口径不同，不把审计候选数直接当作最终删除量。

答案粗分为整数23,205、小数1,504、选项字母候选48、表达式及其他15,558。题干token中位65、P95约179、P99约314，最大3,297；实际学生chat prompt中位88、最大3,320，仅1题超过旧2,048题干预算。训练时18,432序列上限还包括生成解答及教师条件，不能直接用来评价题干长短或题目难度。

代表性问题包括：

- 原始行786/1401是同一道合作做纸杯蛋糕题，标准答案分别为25和20，但两条参考解答都算到25。说明重复题需要同时核对标准答案，不能任取一条。
- 行65要求读取图中x/y，但题干没有提供图或替代定义；行9833的problem实际上是家庭购车的计算过程及结论。前者缺必要上下文，后者是解答片段混入题干。
- 一些几何题含完整Asymptote且条件充分，可以使用；另一些题只有缺失图片链接。不能按“含figure”或“含绘图代码”一律删除。
- 很多参考解答的最后boxed包含选项和数值，如`\textbf{(D)} 25`。简单字符串不相等不能直接说明错标；这也是后续参考终答检查要规范选项注记的原因。

原始参考解答既有非boxed结论，也有格式混排，早期仅用现有grader判最后boxed时，2,084条判等、2,376条未判等、2,930条没有可提取最后boxed、1条提取异常。这是工具覆盖统计，不能作为原始数据错误率。参考解答终答相符也不能证明其中全部推理正确。

## 3. 实际清洗流程

用户确定的运行规则为：全自动；每条输入只有“可用”或“排除”；无法自动闭环则排除并记原因；难度只有易/中/难；先完成清洗，再给可用题打标签。没有给用户安排人工处理环节。

### 3.1 字段和文本规范化

检查题干及答案类型、空值、乱码和明显解答片段。保留Unicode变量、大小写、数值、运算符、LaTeX与Asymptote换行，原始题目内容不作语义改写。精确匹配键保留词元边界，避免把`a b`混同于`ab`、把`x_1`混同于`x1`。

缺answer直接排除；空solution保留。当前OPD教师看题目和学生初始解答，不使用原始专家解答，因此空solution不能成为整题删除条件。分数、符号表达式、完整选择题可以保留。

标准答案仅进行安全外层格式和明确数值/分数等价处理。同题但无法自动证明答案相容时，整个题组排除，不依靠多数投票、不补写答案、不更改原题。

### 3.2 原始来源冲突与精确去重

以规范化题干建立题组；同题答案相容时保留确定性的代表，原始有参考解答作为同题选择时的优先条件之一。来源答案或原领域/难度标签冲突时排除整组。正式CPU阶段从40,315条中保留38,839个代表，产生1,476条初步排除决策。

### 3.3 近重复与训练—测试排重

CPU以数学词元trigram、64维MinHash、16个LSH band召回训练内部候选，阈值0.82；测试侧再用倒排扫描进行更宽松的候选召回，阈值0.45，避免只依赖LSH。保留数字和条件，由8B判断是否为相同实例。

本次共589对候选，其中2对属于训练—测试候选。GPU判定总计288对同题、273对不同实例、28对无法明确区分。后者按已确定的保守规则排除关联训练组；同题型换数字若判为不同实例则保留。未触发候选数量上限或超大桶排除。

两对测试候选中，一对判同题，一对判不同实例。判同题的是原始训练行5696与BeyondAIME索引30：同一二十面体染色问题，训练答案61917364224，测试只追加答案模1000，答案为224。因此训练侧该组被排除。此前规范化文本完全匹配为0，说明只查全等不足以识别这种重合。

这次“污染排查”的范围是当前训练数据与这229道最终测试题的可见文本、同题改写和简单答案变换。它不等于追溯基座模型预训练语料，也不构成对所有未召回语义改写的完全排除证明。

### 3.4 GPU内容清洗

通过前面步骤后，38,483个代表进入8B内容判断。模型检查任务是否完整、关键图形/条件是否缺失、是否为解答片段、题干是否直接泄露所求答案、标准答案或任务是否明显矛盾。输入中的gold answer是独立字段，字段存在本身不算题干泄露答案。

模型采用非思考模式，只输出通过码或排除原因码，最多8 tokens。结构化输出和有限枚举保证结果可解析，技术失败与内容判定分开统计。内容阶段通过33,236题；排除理由传播到相关重复组后，原始40,315条最终均有且只有一条二元决策。

## 4. 领域和难度标签

首先匹配官方`KbsdJames/Omni-MATH`原题，固定revision为`40ba231d8f16e29ecd40e6407e2c8640145a8f62`。审计发现3,528条本地记录能匹配来源，其中3,469条单一匹配；59条多匹配中有31条难度值冲突。正式清洗仍需经过来源答案、标签及内容检查，最终3,050条可用题沿用可靠来源标签。

原Omni分数≤3映射易、>3且≤5映射中、>5映射难，保留原分数和来源。其余30,186题使用Qwen3-8B非思考模式自动标注。只输入题目和固定示例，输出简短枚举，如`geometry,medium`，上限8 tokens。数学领域分为代数、几何、数论、组合与概率、微积分、其他，难度仅易/中/难。

粗分层标准：易为基础概念、常规计算或直接方法；中为多步推导或常见竞赛技巧；难为奥赛构造、综合推理或非常规方法。模型标签是先验粗分层，不是4B学生多次解题测得的成功率；本次没有为全量题生成完整解答或做pass@k校准。

初期短数码输出测试出现领域过多归入代数，实施时改用语义明确的英文枚举，并补充几何、数论及常规计算的固定示例。当前标签及来源已经冻结；后续若调整标签规则，应产生新版本，不覆盖现有实验所依赖的记录。

## 5. 双卡并行和实测成本

CPU初始16 workers处理字段、来源匹配、精确去重及近重复召回；这些操作与两个GPU副本加载并行。每卡一个BF16 8B副本、TP1、显存份额0.85、上下文上限4,096、token批预算32,768、前缀缓存，默认eager模式减少短任务冷启动。模型全程常驻，清洗和分层阶段复用。

同一常驻模型比较有效batch64/128，实测合计请求吞吐约284.72/341.63条每秒，选择128。两卡分别处理35,282和34,376个请求；这些请求包含候选判断、预热/测速、内容清洗和标签，不等于独立题目数。

| 实际阶段 | 处理范围 | 耗时 |
| --- | --- | ---: |
| 模型加载 | 两个8B副本并行 | 各约13.58秒 |
| 候选判断 | 589对 | 约4.40秒 |
| 内容清洗 | 38,483个代表 | 约117.22秒 |
| 清洗整体 | 包含CPU、模型等待、候选及内容处理 | 约142.14秒 |
| 补标签 | 30,186题 | 约97.33秒 |
| 开始处理到最终导出 | 完整40,315题流程 | 约245.77秒 |

阶段存在重叠，不能简单相加。245.77秒统计到导出完成，最终SwanLab同步和进程退出另计。60分钟是原设计运行预算，并非这次实际耗时。全量运行技术排除0，结束后两GPU显存均回到0MiB。

全量清洗和标签实验：[SwanLab oqwvc29e](https://swanlab.cn/@WangZIyu/trd-math-opd/runs/oqwvc29e)。本地完整日志：`data/processed/math-v1/logs/20261115-085622-all/`。初期审计、小样本回归和CPU规模检查的记录见HISTORY与`VALIDATION.json`。

## 6. 已落地的验证集、训练池和首轮训练集

### 6.1 数量和用途

| 数据部分 | 题数 | 使用范围 |
| --- | ---: | --- |
| 清洗后完整可用集 | 33,236 | 冻结的数据工程基底 |
| 验证集 | 512 | 固定留出，主要用于前述参考解答PPL/KL比较 |
| 训练池 | 32,724 | 全部可供后续训练选用的题目，已剔除验证集 |
| 首轮训练子集 | 9,984 | 当前暂定实际训练输入 |
| 训练池中其余后备 | 22,740 | 扩充来源，当前不参与首轮训练 |

训练池包含首轮子集和后备，两者互斥；验证集与整个训练池互斥。原始40,315条复现版本、完整可用33,236条和当前首轮9,984条是不同数据范围，实验报告要写清使用哪一种。

### 6.2 验证集选择

验证集512题占完整可用集1.54%。按全体难度比例先分配为易69、中331、难112，再在每档内按领域分配；对18个非空领域×难度组合最低保留1题，受整数取整影响允许少量比例偏差。

为支持参考解答PPL/KL，选择范围限定为非空solution题。6,305条非空参考中，排除已知性能pilot来源后有6,267条候选；pilot来源包括原始索引0–31及既有8题真实rollout清单。这个排除指已知本项目试跑来源，与基座预训练是否见过无关。

参考检查先提取最后boxed，去掉明确的前置选择题注记，再检查与标准答案的安全等价；只有少数层的候选不足时，使用带1秒解析/比较超时的Math-Verify检查终答。总计形成2,661条自动终答一致的候选（2,657条快路径、4条符号工具补充），其中按固定种子选择512条，508条来自快路径、4条来自符号工具。

这不是把未通过参考检查的题从训练池中删除：当前OPD可以不使用原solution，训练池仍保留除验证集外的所有清洗可用题。终答一致只检查答案接口，不能证明全部推理；这份验证集也具有“有参考解答且可自动验证终答”的子分布边界。

512题的原参考文本冻结，不重新生成、不修补；学生tokenizer下共234,375个response tokens，均值457.76，中位445.5、P95 840.9、最大1,674。题目、参考解答和后续评分模板要固定，当前还没有运行PPL/KL模型评分。

### 6.3 训练抽样与扩充顺序

当前balanced配置的全局有效batch为：

```text
2张卡 × 每rank batch 2 × 梯度累积32 = 128
```

最接近10,000且对齐128的数量是9,984，等于78个有效batch。对齐的是全局有效batch，不需要题数为2的幂。1 epoch对应78个名义优化器更新；后续生成、token长度或目标质量过滤若又删样本，实际步数会变化，届时要记录变化或从后备按顺序补足。

抽样保留训练池自然的领域×难度比例，不按三档各取相同数量。每层先用种子20261115和稳定原始ID生成确定性哈希顺序，再以加权缺额方式交织各层，形成32,724题的固定训练池顺序。首轮取前9,984题，其余为后备。训练DataLoader仍可按固定训练seed打乱，不把文件中的交织顺序当作课程学习安排。

这种顺序使未来取更长前缀时保留首轮全部样本，且无需重新抽样验证集。扩充时保持已冻结验证题、原参考及ID清单；若增加全新的数据来源，应重新清洗，并对最终测试集及这512题做排重，再加入训练池。

### 6.4 冻结与隔离检查

划分种子、输入parquet SHA256、脚本SHA256、各集合的ID文件及parquet SHA256都写入manifest。实际检查包括：

- 原始ID、题目sample_id及duplicate_group_id在各集合内部唯一。
- 验证集与整个训练池，在以上三种ID上均为0交集。
- 首轮训练集为训练池的固定前缀，训练子集与后备为0交集。
- 验证集加训练池恰好覆盖全部33,236题，训练子集加后备恰好覆盖训练池。
- 512题均有非空参考解答和终答一致性检查记录，领域及难度合法；18层均有覆盖。

这里的题组隔离基于前述全局清洗识别的重复组，不额外声称完成了所有数学语义变体的形式证明。划分实验与CPU处理上传到[SwanLab qc1pyqma](https://swanlab.cn/@WangZIyu/trd-math-opd/runs/qc1pyqma)。实际选择、导出和检查约4.04秒（SDK连接、最终同步另计），没有使用GPU。

## 9. 方法参考及适用边界

- [DeepScaleR原数据卡](https://huggingface.co/datasets/agentica-org/DeepScaleR-Preview-Dataset/blob/b6ae8c60f5c1f2b594e2140b91c49c9ad0949e29/README.md)：允许空solution；本项目按题目和标准答案完整性处理。
- [Big-Math](https://arxiv.org/html/2502.17387v1)：借鉴去重、评测排重与可验证性筛选；没有照搬其全量长解题或64次采样难度估计。
- [Omni-MATH](https://arxiv.org/html/2410.07985v1)与[固定来源版本](https://huggingface.co/datasets/KbsdJames/Omni-MATH/tree/40ba231d8f16e29ecd40e6407e2c8640145a8f62)：回填可对齐的原始标签，并保留模型辅助评级的局限。
- [Open R1数据验证经验](https://huggingface.co/blog/open-r1/update-3)：区分格式、答案等价工具覆盖与真实题型质量，避免把所有无法解析情况解释为数学错误。

本次不报告清洗后模型准确率提升，没有用最终测试分数调筛选阈值。数据工程完成后的效果应由后续固定验证及独立测试评估；本记录先冻结可复现的输入范围、自动决策和比较口径。
