# 教师改写数量与通过率：逐条缓存复核

日期：2026-11-16。仅读取既有学生/教师缓存，没有新训练、生成或GPU评分。原始训练范围为**9,984条**，不是9,998条。已核对逐条标准答案一致、教师收到的initial_response与学生保存回答一致，并复核两份文件SHA256。

## 用户询问的三个指标

| 问题 | 核对结果 |
| --- | --- |
| 学生原始回答通过多少条？ | 7,153 / 9,984，71.64% |
| 教师有没有完全没改的？ | 整段回答逐字相同0条；9,984条文本均不同 |
| 去掉教师思考后，是否只是原样复制？ | 9,949条有闭合思考段和非空最终解答，全部与学生原文不同；去掉首尾空白、忽略全部空白两种比较均无完全相同。另35条思考未闭合，无法同口径分出最终解答 |
| 改写后通过率是多少？ | 原有“整个响应最后boxed”口径7,310 / 9,984 = 73.22%；严格仅检查思考结束后的最终解答，可确认通过7,302 / 9,984 = 73.14% |

“文本不同”只能证明不是逐字复制，不能证明数学方法有实质改变或质量提高。即使初始答案正确，教师仍可能重新组织同一条解法。

## 本次发现的8条旧评分口径差异

旧口径在整个教师响应中寻找最后boxed，思考段中的答案也可能被判分。本次严格分出最终解答后：

- 4条旧判通过来自没有闭合思考的响应，无法确认完整最终解答。
- 另外4条有闭合思考，但最终解答没有通过，整个响应中的通过答案来自思考段。
- 因而旧7,310条通过中，有8条不能计作已确认的最终解答通过；严格计数为7,302。
- 仅在有完整最终解答的9,949条内计算，通过率为7,302 / 9,949 = 73.39%。以全部改写请求为分母则为73.14%；35条未闭合视为尚未验证出正确最终解答，而不是证明数学答案错误。

之前报告的7,310、206、49保留为旧全响应评分结果。本次更严格的最终解答审核应优先用于后续目标筛选，不能混用两套分母或评分口径。

## 转移表揭示了纠错能力的局限

旧全响应口径便于与既有统计核对：通过→通过7,104；未通过→通过206；通过→未通过49；未通过→未通过2,625。

严格最终解答口径：

| 学生原始回答 | 教师最终解答 | 条数 |
| --- | --- | ---: |
| 通过 | 通过 | 7,099 |
| 通过 | 未通过 | 46 |
| 未通过 | 通过 | 203 |
| 未通过 | 未通过 | 2,601 |
| 通过8条、未通过27条 | 思考未闭合，最终解答不可确认 | 35 |

学生原始未通过共2,831条，教师修正并得到可确认最终解答的只有203条，**纠错率约7.17%**。其余2,601条仍未通过，27条无法确认最终解答。因此“改了很多字”与“修正了多少原有错误”差别很大。多数最终通过来自原来已经通过的题，不能把73%的整体通过率当作73%的纠错率。

评分器仅检查末尾boxed答案的字符串/数值等价，不证明完整推理正确；某些符号等价可能被漏判。以上“通过/未通过”均遵循这个边界。

## 对是否继续训练的判断

这组结果不支持继续将当前全量改写不经筛选地直接用于同样训练；既有AIME25成绩也没有显示收益。优先暂停扩大这套训练，保留全部原始缓存，先处理目标质量和学生可进入的前缀。

但数据仍有可用部分：203条已确认纠错目标，以及7,099条保持最终正确的改写。后者是否有新的有效推导、是否更适合学生，需要进一步检查；并非只要原本答对，其改写就必然没有训练价值。46条通过→未通过、2,601条仍未通过及35条未闭合，不应作为已确认优质目标照单全收。也不能只凭轻量验证器直接删除所有未通过的符号题。

这评价的是当前教师、提示、生成设置和目标构造的组合，不足以否定所有教师改写方法。下一步应先用现有缓存构造最终解答目标及分组质量审核，再用独立生成验证做小规模对照；本次未启动这些训练。
